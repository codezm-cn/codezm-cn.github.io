浅谈四个路由协议（RIP,OSPF,IS-IS,BGP）以及其配置教程

常见路由协议简介与要点

1. RIP

全称路由信息协议，Routing Information Protocol

其使用跳数（Hop Count）来衡量到达目的地址的距离，称为度量值。在缺省情况下，路由设备到与它直接相连网络的跳数为0，通过一个路由设备可达的网络的跳数为1。也就是说，度量值等于从本网络到达目的网络间的路由设备数量。

为限制收敛时间，RIP规定度量值取0～15之间的整数，大于或等于 16 的跳数被定义为目的网络或主机不可达（Network Unreachable）。由于这个限制，使得RIP不可能在大型网络中得到应用。

RIP 路由器默认每 30 秒使用UDP520端口发送一次路由表，如果在 180 秒之内没有收到路由的更新，则将该路由置为无效，在 120 秒内还没收到这条路由的更新，就从路由表中将该路由删除。

2. OSPF

全称开放式最短路径优先，Open Shortest Path First

其通过在自治系统（AS，autonomous system）中划分区域（骨干、普通、末梢STUB）和选举主备路由器DR和BDR，利用Dijkstra最短路径算法生成最短路径树，建立并维护链路状态数据库（LSDB,Link State Database）。

OSPF用IP报文直接封装协议报文，协议号为89。OSPF分为5种报文：Hello报文、DD报文、LSR报文、LSU报文和LSAck报文，翻译下来分别是哈喽报文、数据库描述报文、链路状态请求报文、链路状态更新报文、链路状态确认报文。

注意区分LSA（链路状态通告）和LSAck，LSA是链路状态信息，被封装在DD、LSU报文中传递；LSR用来请求LSA，LSAck用来确认LSA。

3. IS-IS

全称中间系统到中间系统，Intermediate system to intermediate system

其特性与OSPF有一定关系：是一种链路状态协议，使用最短路径优先SPF算法进行路由计算，选举DIS和非DIS（与OSPF中的DR和BDR类似）。

分为三种路由器：L1路由器、L2路由器和L1/L2路由器。其中，L1路由器是为端系统直接提供服务的路由器，L2路由器是骨干路由器。L1/L2 路由器负责把 L1 区域的路由泄露/汇总进 L2 骨干，同时向 L1 区域自动下发一条默认路由，形似桥梁。

分为三种报文：HELLO PDU（Protocol Data Unit）、LSP（Link State PDUs）和SNP（Sequence Number PDUs）翻译为Hello报文、链路状态报文、序列号报文。

适用于大型运营商。

4. BGP

全称边界网关协议，Border Gateway Protocol

其使用TCP179端口作为其传输层协议，通过自治系统（AS）的内外关系分为内部（Internal）BGP和外部（External）BGP，也就是常说的IBGP、EBGP。

5. 分类与关系

特性 OSPF RIP BGP

ENSP中cloud的使用教程

在学习网络工程师的过程中，ensp中的cloud一直让人疑惑，他是云服务器吗？怎么用？怎么设置接口？

但实际cloud并不是连接云端，而是打通实体网络的通道，而不局限于ensp内部的设备

得知此功能后，我尝试通过ensp连接我的Ubuntu Linux虚拟机，下面是操作过程：

本次的环境中，安装ensp的设备是虚拟机Windows 10（为了确保纯净的环境能正常启动）于是网卡均连接到VM中的NAT模式，确保在同一网段

cloud的配置如图所示

先创建udp端口，类型默认为Eth或GE，第二个创建本地网卡，绑定信息为ethernet0

不同设备可能不同，如果需要在visualbox配置的虚拟机需要将绑定信息设置为VirtualBox Host-Only Network #X

入端口编号1，出端口编号2，勾选双向通道，端口类型需与创建端口的一致

随后配置PC的IP （需与nat网段一致同时确保不冲突，可以提前查看Linux、主机的IP），启动设备即可

可以先尝试ping安装ensp的主机，再到网关，最后再pingLinux或者其他设备

无法连接的排查：

  1. 使用 display interface brief 检查接口是否全开 （可能有拓扑显示已连接但是接口是down的情况）

  2. 使用抓包或 arp -a 检测Windows设备是否有看见ensp的设备的ip

  3. 尝试关闭Windows防火墙 注意内网环境安全关闭，或者其他杀毒软件

  4. 尝试重启设备或ensp 可能是ensp的bug或visualbox异常

补充笔记

display current-configuration

显示比较详细的信息，如默认的设置（设备名、cluster集群 ntdp路由交换 ndp邻居发现、aaa用户配置、接口情况）

display this

能简化一些，或者看当前配置下的操作配置

display interface

可以看接口状态，和该设备的mac地址（hardware address）

display interface brief

可以看接口是否开启关闭

FTP搭建与防范

搭建FTP服务器时，FTP协议默认以明文传输用户名、密码和文件内容，极易被同网段设备嗅探窃取。若需安全传输，应优先采用SFTP（基于SSH加密）替代传统FTP。

FTP基础搭建指令

#安装vsftpd
sudo apt install vsftpd -y
sudo systemctl enable vsftpd    #自启动
sudo systemctl start vsftpd    #启动服务

#创建一个ftp用户
sudo adduser ftpuser --disabled-password --gecos ""  # 创建无密码登录权限的用户
sudo passwd ftpuser  # 设置密码（实验用，实际环境需强密码）
sudo mkdir -p /srv/ftp  # 主目录
sudo chown ftpuser:ftpuser /srv/ftp    # 文件权限设置
sudo chmod 755 /srv/ftp  # 读写权限

sudo mkdir -p /srv/ftp/data    # 正常上传修改下载的目录
sudo chown ftpuser:ftpuser /srv/ftp/data
sudo chmod 755 /srv/ftp/data

其中配置文件 /etc/vsftpd.conf 配置：

listen=NO                # 独立模式
listen_ipv6=YES
anonymous_enable=NO      # 匿名登录
local_enable=YES
write_enable=YES
chroot_local_user=YES    # 主目录限制
secure_chroot_dir=/var/run/vsftpd/empty    # 环境设置
local_root=/srv/ftp      # ftp主文件夹
xferlog_enable=YES
connect_from_port_20=YES
ssl_enable=NO

随后可以用Windows资源管理器/MT管理器（安卓）访问，需要输入账号（ftpuser）和密码
